## Root Level

```
nix-darwin/
├── flake.nix              # Flake definition (entry point)
├── flake.lock             # Locked dependencies
├── CLAUDE.md              # AI assistant instructions
├── README.md              # Project overview
├── .gitignore             # Git ignore patterns
└── [directories...]
```

### flake.nix

**Purpose:** Main entry point for the entire configuration

**Contains:**

- Input declarations (nixpkgs, nix-darwin, home-manager)
- System configurations (mbp-jimmy, mbp-work)
- Helper function `mkDarwinSystem`

**Example:**

```nix
{
  description = "Jimmy's Nix Darwin Configuration";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";
    nix-darwin.url = "github:LnL7/nix-darwin";
    home-manager.url = "github:nix-community/home-manager";
  };

  outputs = { self, nix-darwin, home-manager, nixpkgs }: {
    darwinConfigurations = {
      mbp-jimmy = mkDarwinSystem { ... };
      mbp-work = mkDarwinSystem { ... };
    };
  };
}
```

### flake.lock

**Purpose:** Lock file for reproducible builds

**Contains:** Exact commit hashes of all inputs

**Generated by:** `nix flake update`

**Version controlled:** Yes, commit to git

**Update:** `nix flake update` or `update-nix`

## Hosts Directory

```
hosts/
├── mbp-jimmy/
│   ├── default.nix        # Personal Mac config
│   └── secrets.yaml       # Encrypted secrets (sops-nix)
└── mbp-work/
    ├── default.nix        # Work Mac config
    └── secrets.yaml       # Encrypted secrets (sops-nix)
```

### Purpose

Per-machine system configuration. Each hostname has its own directory.

### hosts/mbp-jimmy/default.nix

**Purpose:** Personal MacBook configuration

**Contains:**

- Hostname and computer name
- System settings specific to personal Mac
- Hardware-specific settings (if any)
- sops-nix secrets configuration

**Example:**

```nix
{ pkgs, ... }: {
  networking.hostName = "mbp-jimmy";
  networking.computerName = "Jimmy's MacBook Pro";

  # Personal-specific system settings
  system.defaults = {
    # ... personal Mac settings
  };

  # Secrets management
  sops.defaultSopsFile = ./secrets.yaml;
}
```

### hosts/mbp-work/default.nix

**Purpose:** Work MacBook configuration

**Contains:**

- Hostname and computer name
- Work-specific system settings
- Work-specific system packages (if any)

**Example:**

```nix
{ pkgs, ... }: {
  networking.hostName = "mbp-work";
  networking.computerName = "Jimmy's Work MacBook";

  # Work-specific Homebrew casks
  homebrew.casks = [
    "slack"
    "zoom"
  ];
}
```

### When to Edit

- Setting up a new machine
- Changing hostname or computer name
- Adding host-specific system settings
- Installing host-specific GUI apps

### modules/darwin/

**Purpose:** macOS-specific system configuration (Nix-Darwin)

**Scope:** System-wide settings

**Requires:** Root privileges

#### system.nix

**Purpose:** macOS system defaults and preferences

**Contains:**

- Dock settings
- Finder preferences
- Trackpad settings
- Keyboard settings
- Screen capture settings

**Example:**

```nix
system.defaults = {
  dock = {
    autohide = true;
    show-recents = false;
    orientation = "bottom";
  };

  finder = {
    AppleShowAllExtensions = true;
    FXPreferredViewStyle = "Nlsv";  # List view
  };
};
```

#### homebrew.nix

**Purpose:** Homebrew package and cask management

**Contains:**

- Homebrew setup
- Taps (third-party repositories)
- Brews (CLI tools)
- Casks (GUI applications)
- Mac App Store apps

**Example:**

```nix
homebrew = {
  enable = true;

  taps = [ "homebrew/cask-fonts" ];

  brews = [
    "mas"  # Mac App Store CLI
  ];

  casks = [
    "docker"
    "visual-studio-code"
    "claude-code"
  ];

  masApps = {
    "Xcode" = 497799835;
  };
};
```

#### fonts.nix

**Purpose:** System font installation

**Contains:**

- Nerd Fonts for terminal
- Programming fonts
- System fonts

**Example:**

```nix
fonts.packages = with pkgs; [
  (nerdfonts.override { fonts = [ "Meslo" "FiraCode" ]; })
];
```

### modules/shared/

**Purpose:** Shared configuration across Darwin and potential Linux systems

#### packages.nix

**Purpose:** System-wide package installation

**Contains:**

- CLI tools
- Development tools
- System utilities
- Shared packages for all users

**Example:**

```nix
environment.systemPackages = with pkgs; [
  # Modern CLI tools
  bat eza ripgrep fd

  # Development
  git gh

  # System tools
  htop btop
];
```

#### users.nix

**Purpose:** User account definitions

**Contains:**

- User account settings
- User shell
- User home directory

**Example:**

```nix
users.users.jimmy = {
  name = "jimmy";
  home = "/Users/jimmy";
  shell = pkgs.zsh;
};
```

## Configuration Organization Practices

### 1. Separate Concerns

**Do:** Keep each type of configuration in its appropriate file

```nix
# ✅ Good: Git config in git.nix
# home/jimmy/programs/git.nix
programs.git = {
  userName = "Jimmy";
  aliases = { ... };
};

# ✅ Good: Shell aliases in zsh.nix
# home/jimmy/shell/zsh.nix
home.shellAliases = {
  ll = "ls -la";
};
```

**Don't:** Mix different concerns in one file

```nix
# ❌ Bad: Git settings in zsh.nix
# home/jimmy/shell/zsh.nix
programs.git.userName = "Jimmy";  # Wrong file!
home.shellAliases = { ... };
```

### 2. Use Appropriate Layers

**System Layer** (modules/) - System-wide settings:

```nix
# ✅ modules/shared/packages.nix
environment.systemPackages = [
  pkgs.git  # Available to all users
];
```

**User Layer** (home/) - User-specific settings:

```nix
# ✅ home/jimmy/programs/git.nix
programs.git = {
  userName = "Jimmy";  # User-specific
};
```

### 3. Follow the Mixin Pattern

**Shared config** → base.nix

```nix
# ✅ home/_mixins/base.nix
programs.starship.enable = true;  # Same on all machines
```

**Machine-specific** → personal.nix or work.nix

```nix
# ✅ home/_mixins/personal.nix
home.sessionVariables.MACHINE_MODE = "home";

# ✅ home/_mixins/work.nix
home.sessionVariables.MACHINE_MODE = "work";
```

**Don't:** Put machine-specific config in shared files

```nix
# ❌ Bad: Work-specific in zsh.nix (shared)
home.shellAliases = {
  vpn = "sudo openconnect vpn.company.com";  # Work only!
};
```

### 4. Group Related Settings

**Do:** Keep related settings together

```nix
# ✅ Good: All Python config in one place
# home/jimmy/development/python.nix
{
  home.packages = with pkgs; [
    uv
    micromamba
    python311
  ];

  home.shellAliases = {
    uv-new = "uv init";
    uv-add = "uv add";
    base = "micromamba activate base";
  };

  home.file.".condarc".text = ''
    # Micromamba config
  '';
}
```

## Git Workflow Practices

### 1. Commit Frequently

```bash
# After making changes
cd ~/nix-darwin
g s              # Check what changed
g d              # Review diff
g aa             # Add all
g cm "Add weather alias"
g ps             # Push

# Make commits focused and atomic
# One change = One commit
```

### 2. Write Clear Commit Messages

**Good commit messages:**

```bash
g cm "Add Python auto-activation feature"
g cm "Fix: gitconf command not working"
g cm "Update: switch to g prefix for git aliases"
g cm "Docs: add troubleshooting guide"
```

**Bad commit messages:**

```bash
g cm "changes"
g cm "update"
g cm "fix stuff"
```

### 3. Test Before Committing

```bash
# Edit config
nixconf

# Test it works
nix-rebuild
exec zsh

# Verify changes
g s
test-your-changes

# Only then commit
g aa
g cm "Add new feature"
g ps
```

### 4. Keep Working State in Git

```bash
# After successful rebuild
g aa
g cm "Working config: $(date +%Y-%m-%d)"
g ps

# Now you can safely experiment
# Worst case: g revert or nix-rollback
```

### 5. Use Branches for Experiments

```bash
# Experiment with new feature
g cob experiment/new-prompt

# Make changes
# Test thoroughly

# If works
g co main
g merge experiment/new-prompt
g ps

# If doesn't work
g co main
g branch -D experiment/new-prompt  # Discard
```

### 6. Tag Stable Versions

```bash
# After major successful changes
g tag -a v1.0 -m "Stable configuration with Python auto-activation"
g push --tags

# Later, if needed, check out stable version
g co v1.0
```

## Testing Changes Practices

### 1. Start Small

**Don't:** Change everything at once

```bash
# ❌ Bad approach
# Edit 10 files
# Add 20 packages
# Change 50 aliases
nix-rebuild  # Something breaks, no idea what
```

**Do:** Make incremental changes

```bash
# ✅ Good approach
# Add 1 alias
nix-rebuild
# Test it works

# Add 1 package
nix-rebuild
# Test it works

# Commit working state
g aa
g cm "Add neofetch"
```

### 2. Use Dry Run

```bash
# See what would change
darwin-rebuild build --flake . --dry-run

# Check flake syntax
nix flake check

# Show what would be built
nix build .#darwinConfigurations.mbp-jimmy.system --dry-run
```

### 3. Test on Non-Critical Machine First

```bash
# Test new configuration on personal Mac first
# If works well, apply to work Mac

# Personal Mac
cd ~/nix-darwin
# Make experimental changes
nix-rebuild
# Test thoroughly

# If good
g ps

# Work Mac
cd ~/nix-darwin
g pl
nix-rebuild
```

### 4. Keep Rollback Ready

```bash
# Before major changes
g aa
g cm "Before major refactor: $(date)"
g ps

# Make changes
nix-rebuild

# If breaks
nix-rollback  # Instant undo!
```

## Documentation Practices

### 1. Comment Your Configuration

**Do:** Add comments explaining non-obvious settings

```nix
# ✅ Good: Explained
home.shellAliases = {
  # AWS SSO login - requires browser authentication
  awslogin = "aws sso login --profile work-domain";

  # Quick disk usage - shows human-readable sizes
  du-summary = "du -h -d 1 | sort -hr";
};
```

**Don't:** Over-comment obvious things

```nix
# ❌ Bad: Obvious
home.shellAliases = {
  # List files
  ll = "ls -la";  # Comment adds no value
};
```

### 2. Document Custom Functions

```nix
programs.zsh.initExtra = ''
  # Create directory and cd into it
  # Usage: mkcd new-folder
  mkcd() {
    mkdir -p "$1" && cd "$1"
  }

  # Backup file with timestamp
  # Usage: backup important-file.txt
  backup() {
    cp "$1"{,.backup-$(date +%Y%m%d-%H%M%S)}
  }
'';
```

### 3. Keep Documentation Updated

When you modify the configuration:

1. Update relevant docs in `docs/`
2. Update CLAUDE.md if assistant behavior should change
3. Update README.md if setup process changes

## Security Practices

### 1. Use sops-nix for Secrets

**Do:** Use encrypted secrets management

```bash
# Add secrets
edit-secrets

# Check status
secrets-status

# Secrets are encrypted in git
# Safe to commit hosts/*/secrets.yaml
```

**Don't:** Commit plaintext secrets

```bash
# ❌ Never commit:
# - API keys
# - Passwords
# - Private SSH keys
# - AWS access keys
```

### 2. Review Before Committing

```bash
# Review all changes
g d

# Look for patterns like:
# - API_KEY=
# - password=
# - secret=
# - token=
# - aws_secret_access_key

# If found plaintext secrets, use edit-secrets instead!
```

### 3. Backup Age Keys

```bash
# CRITICAL: Backup your age key
# Without it, you cannot decrypt secrets!

# Location: ~/.config/sops/age/keys.txt
cp ~/.config/sops/age/keys.txt ~/secure-backup/

# Store backup safely (NOT in nix-darwin repo!)
```

### 4. Use Secure Permissions

```bash
# After rebuild, verify permissions
```

## Anti-Patterns to Avoid

### 1. Don't Use Imperative Commands

**Avoid:**

```bash
# ❌ Installing packages imperatively
nix-env -iA nixpkgs.ripgrep

# Problem: Not tracked in config, not reproducible
```

**Instead:**

```nix
# ✅ Declarative package management
# modules/shared/packages.nix
environment.systemPackages = [ pkgs.ripgrep ];
```

### 2. Don't Bypass Nix

**Avoid:**

```bash
# ❌ Manual installation
curl -o ~/bin/tool https://...
chmod +x ~/bin/tool

# Problem: Not managed, not reproducible
```

**Instead:**

```nix
# ✅ Use Nix or Homebrew
# If in nixpkgs:
environment.systemPackages = [ pkgs.tool ];

# If not, use Homebrew:
homebrew.brews = [ "tool" ];
```

### 3. Don't Edit Generated Files

**Don't edit:**

- `~/.zshrc` (generated by Home Manager)
- `~/.config/git/config` (generated by Home Manager)
- `~/.config/starship.toml` (generated by Home Manager)

**Instead, edit source:**

- Edit `home/jimmy/shell/zsh.nix`
- Edit `home/jimmy/programs/git.nix`
- Edit `home/_mixins/base.nix`
- Rebuild: `nix-rebuild`

### 4. Don't Duplicate Configuration

**Avoid:**

```nix
# ❌ Duplication
# personal.nix
programs.fzf.enable = true;

# work.nix
programs.fzf.enable = true;
```

**Instead:**

```nix
# ✅ Shared config
# base.nix (used by both)
programs.fzf.enable = true;
```

### 5. Don't Commit Plaintext Secrets

**Avoid:**

```nix
# ❌ Plaintext secrets in config
home.sessionVariables = {
  API_KEY = "sk-1234567890";  # NEVER!
};
```

**Instead:**

```bash
# ✅ Use sops-nix
edit-secrets
# Add encrypted secret

# Reference in config
sops.secrets.API_KEY = {};
```
