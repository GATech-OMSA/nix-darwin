# AWS Multi-Role Quick Reference

**Quick command reference for everyday AWS profile management.**

## 🚀 Daily Commands

### Switch Profile
```bash
# Use support role (read-only, default)
awsuse ti dev

# Use developer role (write access)
awsuse ti dev developer

# Alternative: direct alias
tidev              # support role
tidev developer    # developer role
```

### Login to AWS SSO
```bash
# Login to specific profile
awslogin ti dev

# Login with specific role
awslogin ti qa developer

# Alternative: direct alias + login
tidev && aws sso login
```

### Discovery & Status
```bash
awslist            # List all accounts (grouped by project)
awswho             # Show current active profile
awswhere 123456789 # Find which project/env uses account ID
awscheck           # Check SSO session status for all profiles
```

## 🔑 Available Roles

| Role | Access Level | Usage |
|------|--------------|-------|
| `support` | Read-only (default) | No role parameter needed |
| `developer` | Read + Write | Add `developer` as 3rd parameter |
| `admin` | Full admin | Add `admin` as 3rd parameter |
| Custom roles | Per account config | Use exact role name |

## 🎯 Common Workflows

### Start Your Day
```bash
awslist           # See what's available
tidev             # Switch to TI dev (support)
awscheck          # Verify SSO session
aws s3 ls         # Test access
```

### Deploy to Dev
```bash
tidev developer   # Switch to developer role
aws sso login     # Login if needed
./deploy.sh       # Run deployment
```

### Check Multiple Environments
```bash
awsuse ti dev && aws s3 ls
awsuse ti qa && aws s3 ls
awsuse ti prod && aws s3 ls
```

### Troubleshooting Access
```bash
awswho                    # Which profile am I using?
awscheck                  # Is my SSO session valid?
aws sts get-caller-identity  # What are my actual credentials?
```

## 🔧 Configuration

### Location
- **Profile config**: `~/.aws/config` (generated by nix-darwin)
- **Account definitions**: `~/.aws/accounts.json` (your source of truth)
- **Helper functions**: `lib/aws-helpers.nix`
- **Profile generator**: `home/jimmy/programs/aws.nix`

### accounts.json Format

**Simple (support role only):**
```json
{
  "tririga-integrations": {
    "alias": "ti",
    "accounts": {
      "dev": "123456789012"
    }
  }
}
```

**Advanced (multiple roles):**
```json
{
  "tririga-integrations": {
    "alias": "ti",
    "default_role": "support",
    "additional_roles": ["developer", "admin"],
    "accounts": {
      "dev": {
        "account_id": "123456789012",
        "region": "us-west-2"
      }
    }
  }
}
```

## 🔄 Rebuild Configuration

After editing `accounts.json`:
```bash
darwin-rebuild switch --flake .
exec zsh  # Reload shell for new aliases
```

## ⚠️ Deprecated Commands

These still work but prefer project-specific aliases:
- ~~`awsdev`~~ → Use `tidev`, `psdev`, etc.
- ~~`awssbx`~~ → Use `tisbx`, etc.
- ~~`awsqa`~~ → Use `tiqa`, `psqa`, etc.
- ~~`awsprd`~~ → Use `tiprd`, `psprd`, etc.

**Why?** Generic aliases are ambiguous in multi-project setups.

## 💡 Tips

1. **Always use support role first** for safety (it's read-only)
2. **Use awslist** to discover available profiles
3. **Use awscheck** before running critical commands
4. **Project aliases are clear**: `tidev` = TriRiga dev, not "any dev"
5. **Role parameter is optional**: defaults to support
6. **SSO login persists**: no need to login for every profile switch

## 🐛 Quick Troubleshooting

| Problem | Solution |
|---------|----------|
| "Alias not found" | Run `exec zsh` to reload |
| "SSO session expired" | Run `awslogin <proj> <env>` |
| "Invalid profile" | Run `awslist` to see valid names |
| "Permission denied" | Check you're using right role (add `developer`) |
| "Wrong account" | Run `awswho` to verify current profile |
